# ClientApp2 視窗架構
目前有試寫重構一些功能請先詳細分析!

## 核心設計理念 (Core Philosophy)
本架構仿照作業系統 (OS) 設計，將「系統底層」與「應用程式」完全分離。
- **高內聚、低耦合**：每個 App 都是獨立的元件，不應直接操作外部 DOM 或其他 App。
- **控制反轉 (IoC)**：App 不再自己決定要畫在哪裡，而是由系統提供「共用容器 (Container)」和「底層功能函式」。

## 檔案結構
apps：最外層是共用程式，包含app基本函式、視窗外觀html css等。內層一個資料夾(例：Music)為一個功能所包含的所有檔案
core：系統內核，包含系統管理、視窗管理等核心功能。
mian.js：系統啟動入口，負責註冊 App 和啟動系統。

## 元件職責定義
目前暫定以下幾個，可能會多會少，後續再調整

### 1. System.js (系統內核)
- **職責**：管理系統生命週期、註冊 App、啟動/關閉 App、派發系統權限。
- **目標**：當系統啟動時，它負責加載設定檔、初始化視窗管理員，並維護目前已安裝的 App 清單。

### 2. WindowManager.js (視窗管理員)
- **職責**：處理所有與「視窗外框」有關的行為。
  - 建立視窗外框 (標題列、最小化、關閉按鈕)。
  - 處理視窗的層級 (z-index)、拖拽、縮放。
  - 焦點管理 (點擊某個視窗時讓它置頂)。

### 3. BaseApp.js (應用程式基底)
- **職責**：所有 App 必須繼承的父類別。
- **核心介面**：
  - `init()`: 初始化 App 邏輯。
  - `render()`:  渲染 UI 到容器中。
  - `destroy()`: 當視窗關閉時，清理記憶體與事件監聽器。

### 4. Apps (獨立應用程式)
- **範例**：Music, Twse, File。
- **原則**：只專注於自己的業務邏輯。透過 `this.api` 與系統溝通 (例如：讀取檔案、顯示通知)。

## 開發流程(暫定，如有更好的方式可以提供)
1. **註冊**：在 `main.js` 中向 `System` 註冊 App 資訊。
2. **啟動**：點擊圖示後，`System` 呼叫 `WindowManager` 建立視窗。
3. **實例化**：`WindowManager` 提供一個 DOM 容器給 App，並將 App 實例化。
4. **掛載**：App 在容器中繪製自己的內容。
